# SafelyGo usability review — October 5, 2026

Overall: **4/10**. The app has working flows, but its information hierarchy, error handling, interruption recovery, and staff workflows do not meet a polished mobile-product standard. Scores judge the current experience, not the effort invested or possible future improvements. 5 means usable with substantial friction; 7 means polished; 9–10 means exceptional.

## Method and limits

Used the running Expo web app at a measured 393 × 852 browser viewport with fictional student, owner, and contact accounts. Registered and verified a fresh account through local file-mail delivery; joined the demo campus; submitted a fictional report; reviewed it as staff; sent a test contact invitation; inspected recovery, deletion, and all staff sections; walked through sharing setup and reviewed both sides of an active synthetic walk. Synthetic sharing used fixed fictional campus coordinates through the local API, not the user's actual location. Stopped that session through the app.

This is a phone-sized UI review, not a physical iPhone test. Native keyboards, VoiceOver, permission dialogs, native maps, background GPS, movement, offline recovery, and actual phone dialing are not verified. Password recovery was reviewed up to the reset form; account deletion was reviewed without deleting a real or demo account. Campus approval was assessed from the registration UI and the existing operating process, not a new live institutional approval. The in-app browser became blocked on its web call confirmation; no call was placed, and review continued in Chrome. That preview failure is not treated as an iPhone app defect. No application code was changed during the review.

## Highest-priority findings

1. Preserve unfinished report drafts and warn before discarding them. Reproduced: enter title/body → Home → Reports → new report; fields are blank with no warning.
2. Put incoming and active walks ahead of setup. Home should expose incoming sharing; recipient names and update health must be visible in active sharing.
3. Replace technical validation paragraphs with field-level plain-language errors. Clear feedback when auth mode changes.
4. Give staff a compact report queue and detail screen. Current staff navigation plus heading and Refresh consume roughly the upper half of the phone before useful content.
5. Replace coordinate entry with campus search and an adjustable map boundary. Add useful approval/support status and owner-transfer guidance.
6. Make urgent help actionable through institution-appropriate configured numbers; do not invent a universal emergency number.
7. Explain report statuses and response expectations, and provide a complete review step before sending.
8. Fix the map legend and make marker details informative. Color alone should not distinguish concern types.

The next improvement should target these workflow problems before adding more decorative assets or changing the palette again.
